# 替换素材操作指南

两种常见操作：**给某张图片换声音**、**添加新图片**。

先说一个前提，它决定了下面所有步骤的写法：

> **`data/classify.js` 是脚本自动生成的，任何手改都会被 `build-classify.js` 覆盖。**
>
> 而 `build-classify.js` 每次运行都会：
> 1. 重新生成 `beep-low/mid/high.wav` 三个文件（**覆盖同名文件**）
> 2. 按图片在数组里的位置循环分配声音（`beep-low` → `beep-mid` → `beep-high` → 循环）
> 3. 把整个 `data/classify.js` 重写一遍
>
> 所以**手改完声音后不要再跑 `build-classify.js`**，否则改动静默失效。下面的做法都绕开了这个坑。

---

## 一、给某一张图片换声音

### 推荐做法：用独立文件名，改配置指向它

**为什么用独立文件名**：`build-classify.js` 会覆盖 `beep-*.wav`，但**不认识**你自己新增的文件名，所以你的素材是安全的。

**步骤**

1. 把声音文件放进 `static/classify/audio/`，**取一个和 `beep-*` 不一样的名字**，例如：

   ```
   static/classify/audio/jimi-voice.mp3
   ```

2. 打开 `data/classify.js`，找到那张图片，把 `audio` 改成新路径：

   ```js
   {
     image: '/static/classify/2-jimi.png',
     group: '2',
     width: 85,
     height: 171,
     audio: '/static/classify/audio/jimi-voice.mp3',   // 改这一行
   },
   ```

3. 保存，开发者工具里刷新页面即可（配置是静态引入的，不需要构建）。

**要点**

- 路径以 `/` 开头（相对小程序根目录），不是 `./` 也不是完整网址
- 扩展名写对，文件叫什么就写什么
- 一个声音文件可以被多张图片共用，不用每张都复制一份

### 另一种做法：直接覆盖 beep 文件

只有当那个声音**只有这一张图在用**、或者你确实想让所有用它的图片一起换，才这么做。

比如某张图用的是 `beep-mid.wav`，直接用你的文件覆盖它、保持文件名不变：

```
把你的声音重命名为 beep-mid.wav，覆盖 static/classify/audio/beep-mid.wav
```

**代价**：当前有三种声音，每种被 7 张图片共用。覆盖 `beep-mid.wav` 会让**所有 7 张**一起变声，而且下次跑 `build-classify.js` 会被重新生成的占位音覆盖掉。

### 关于声音格式

现在的占位音是 **PCM WAV，单声道，16000 Hz，16 bit，1 秒**。

替换时**不要求**用同样格式 —— 小程序 `innerAudioContext` 支持 mp3 / m4a / aac / wav 等常见格式，推荐 `mp3`（体积小）。只要：

- 路径在配置里写对
- 文件真的放到了那个路径

如果格式不支持或文件缺失，点击时会弹「声音文件不存在」或「声音播放失败」。

## 二、添加新图片

### 步骤

1. **放到 `static/classify/`**，文件名格式必须是：

   ```
   <前缀>-<名字>.png
   ```

   例如 `4-xindi.png`、`6-feichuan.png`。

2. **前缀决定它归到哪一组**（也决定每行排几个）：

   | 前缀 | 含义 | 每行张数 | 现有数量 | 尺寸区间 |
   | --- | --- | --- | --- | --- |
   | `2` | 小尺寸 | 4 个 | 3 张 | 85–87 × 171 |
   | `4` | 中尺寸 | 2 个 | 13 张 | 170–172 × 169–171 |
   | `6` | 大尺寸 | 2 个 | 5 张 | 170–172 × 256 |

   想要一个新分组就用更大的数字，比如 `8-xxx.png` 会自成一组排在最后。

3. **跑一次生成脚本**：

   ```bash
   node scripts/build-classify.js
   ```

   它会读出新图片的实际像素尺寸、算出该排在组内什么位置、分配一个占位音，然后重写 `data/classify.js`。

4. **校验**（建议）：

   ```bash
   node scripts/verify-classify.js
   ```

   会检查文件是否存在、配置的 `width`/`height` 和实际是否一致、排序是否正确、有没有图片放在目录里却漏进配置。

### 硬性要求

| 要求 | 说明 |
| --- | --- |
| **必须是 PNG** | 脚本会读 PNG 文件头校验，jpg 直接报错「不是 PNG」 |
| **文件名必须是 `<数字>-<名字>.png`** | 不符合的会被忽略，脚本还会提示「未纳入配置的图片」 |
| **内容不能和已有图片重复** | 按 MD5 比对，重复的会打印「跳过重复图片」而不加入 |
| **新增数量不限** | 组内张数不限，落单的行会自动居中显示 |

### 不用手动做的事

- **不用量尺寸** —— 宽高由脚本从 PNG 文件头读出
- **不用排顺序** —— 自动按「前缀分组 + 组内像素面积升序」
- **不用配声音** —— 自动循环分配占位音（`2` 组排 4 个的布局也已自动适配）
- **不用改 `group` 字段** —— 从文件名前缀自动取

### 一个阈值要注意

`2` 开头那组是**一排 4 个**。当前只有 3 张，总宽 281px，未超出可用的 351px。

如果加到 **4 张以上**，总宽会超出屏幕，图片会被自动按比例缩小（`.home-cell--shrink`，`flex-shrink: 1`）—— 不会溢出或错位，但就不再是原始尺寸了。

想让某一组换每行张数，改 `pages/home/index.js` 顶部：

```js
const COLUMNS_BY_GROUP = {
  2: 4,   // 2 开头一排 4 个
};
const DEFAULT_COLUMNS = 2;  // 其余分组一排 2 个
```

## 三、在浏览器里先看效果（可选）

改完素材不用急着开开发者工具，可以先在浏览器里 1:1 看排布：

```bash
# 项目根目录起静态服务
python -m http.server 8765 --bind 127.0.0.1
```

然后浏览器打开 `http://127.0.0.1:8765/scripts/preview-natural-size.html`。

这个预览页**直接读取 `data/classify.js`**，所以和真实配置永远一致，不会脱节。它还会在控制台核对每张图的渲染尺寸，确认没有被拉伸。

> 必须通过 HTTP 打开，直接双击 `file://` 会因为 CORS 读不到配置文件。

```bash
git add -A
git commit -m "描述这次改了什么"
git push
```

被误操作覆盖了就这样救回来：

```bash
git checkout HEAD -- .                              # 回到上次提交
git fetch origin && git reset --hard origin/main    # 回到云端版本
```
